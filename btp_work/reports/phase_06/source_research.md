# Phase 06 research and design consequences

[Additional primary-paper archive/BibTeX](../../source_review/phase06_primary/README.md), [prior routing-aware references](../../source_review/phase05_primary/README.md), [original source manifest](../../source_review/manifest.json).

The proposal's Step4 tries bounded alternatives after actual routing, while the phase contract requires complete-schedule error improvement. The implementation therefore ranks actual routed transitions, tries private legal pair/parking alternatives, reruns the unchanged planner/router and evaluates the full circuit. A one-batch prediction or a shorter local segment is never sufficient for acceptance.

RFT Eq4/5 and its serialized router show why distance or a graph edge is only a candidate-selection signal. The Enola placement/routing sections likewise distinguish geometric proxies and actual compatible batches. ZAP's parking examples and the later routing-aware/scalable placement papers demonstrate that conflict remedies can trade extra distance against parallelism. No such alternative is presumed faster without replaying the emitted batches.

Atomique SectionIV makes history essential: a move changes vibrational state and later gate/loss errors, not only the current duration. The accepted Phase03 model supplies those laws; Phase06 imports its evaluator and checks downstream heating/time/exposure independently. Basic RFT resources have no supported cooling planner, so resource-enabled cooling input is rejected explicitly; cooling is not silently omitted from an enabled device track.

ZAC's SectionV uses bounded move/exchange neighborhoods and approximate future costs. This motivates pair-slot exchanges, orientation flips and parking alternatives, but not importing its zoned device, reuse rules or reported fidelity gains. The ILS primary literature separates perturbation, local search and acceptance; Phase06 uses a deterministic strict-better full-model acceptance rule, finite evaluation caps and a retained feasible incumbent. It does not claim global optimality or adopt uphill annealing acceptance.

Full replay recomputes the prefix and verifies it exactly before the chosen boundary; it is not advertised as an optimized snapshot-resume implementation. The boundary snapshot contains atom/qubit sites, traps, heating, time/exposure, gates, empty basic cooling resources and both RNG states. A changed suffix is replanned with the same algorithm/options and deterministic routing-stream policy. Each rejected trial is discarded; the caller RNG and immutable incumbent are restored.

Weights and Phase05 assignment/parking settings are held fixed. The planned experiment isolates disabled/zero repair, a four-evaluation budget and a twelve-evaluation budget, on two corrected Phase05 controls. Development generator seeds300-303 and known QFT5 smoke are separate from the named regression/unseen-seed evaluation pilot. Any final full-study claims remain Phase07/08 obligations.


## Primary-source verification during completion

The [author-hosted ILS chapter](https://iridia.ulb.ac.be/~stuetzle/publications/LouMarStu10.pdf), Section 3.3, PDF page 16, defines its Better acceptance rule by retaining the incumbent unless the new cost is strictly lower. This supports the conservative acceptance pattern; the choice to use full RFT-model E and tolerance 1e-12 is this project's design. The chapter also discusses stagnation, which is a limitation of this finite improvement-only search.

The [official ZAC v1 HTML](https://arxiv.org/html/2411.11784v1), Section V-A, describes exchange/jump proposals and an iteration stop. Its initial annealing and intermediate-placement estimators concern a different zoned architecture. Here only the neighborhood idea is adapted; the acceptance objective, atom-pair legality, unchanged-prefix checks and replay are independently implemented for RFT. The stored arXiv PDF may be a later version; the manifest retains its exact hash and page count, while this completion check cites the versioned v1 HTML explicitly.

The evaluation settings were frozen before launch. The completed pilot preserves actual local/full-score disagreements as evidence against proxy-only acceptance. Results are reported in [pilot_results.md](pilot_results.md), with every evaluated proposal retained in [repair_audit.csv](repair_audit.csv).
