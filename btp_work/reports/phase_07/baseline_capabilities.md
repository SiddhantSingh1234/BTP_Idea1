# Baseline capabilities and comparison boundaries

| Compiler/track | Addressing and geometry | Input/trace support | Decision for this project |
| --- | --- | --- | --- |
| Pinned RFT, corrected oriented controls and L/A/R | individually addressed CZ; one shared AOD; declared two-plane grid contract | normalized CZ skeleton, explicit derived transfers, common checker and model | paired primary comparisons supported within declared analytical scope |
| Corrected DasAtom | same requested grid, interaction/restriction radii; complete declared register restored | partition/VF2/native route plus preserved corrective routing; common trace/model | existing 66-target anchor reused; new-circuit comparisons require new bounded compilations, not inferred from older circuits |
| Enola | its scheduling/routing and pulse model carry architecture-specific constraints | vendor implementation exists, but a complete matched normalized-register/geometry/common-error adapter is not established | document feasibility; do not rank its published numbers against new common-model results |
| Atomique | heterogeneous/fixed and reconfigurable arrangements; architecture-specific scheduling/resource assumptions | movement/heating model informed Phase03; importing equations does not supply a matched compiler adapter | source/model reference; no directly matched extra-baseline result claimed |
| ZAC and later zoned compilers | storage/entangling zones, reuse and often global Rydberg exposure | different architecture and physical resources | related work; separate architecture study would be necessary |

The common validator separates structural correctness, declared geometry and unsupported native physical checks. Every new factorial result must pass the common declared model; none is represented as measured device fidelity. The original one-qubit circuit is retained and independently restored for tiny semantic proofs, while physical score scope remains the normalized CZ skeleton.

The supplied DasAtom and device-model papers explicitly discuss architecture/spacing differences, so published cross-paper speed/fidelity ratios cannot substitute for matched local runs. The source [review](../../source_review/SOURCE_REVIEW.md), [technical contracts](../../plan/TECHNICAL_CONTRACTS.md), and existing [benchmark report](../benchmark_report_20261030_all_graphs/README.md) record these limitations. No speculative extra compiler adapter has been labelled complete.
